# Universal Self Drive Cars — Next.js + Neon + HeroUI

A full-stack, responsive self-drive rental website modeled on the screenshots supplied by the project owner. Public visitors browse/filter cars, inspect specifications and prices, and send a **car-specific prewritten WhatsApp message**. Staff use a protected admin panel to edit site content and follow up submitted enquiries.

## Stack

- Next.js 16 App Router, React 19, TypeScript, Tailwind CSS 4, HeroUI 3, Lucide icons
- Neon serverless PostgreSQL, Prisma ORM 6, Zod validation
- Admin email/password login with bcrypt password hashes, signed JWTs, secure HttpOnly cookies and database-backed revocation
- Public car browsing and booking enquiries without customer accounts
- No payment gateway, SMS OTP, or WhatsApp Business API required for the core flow

## 1. Install

Use Node.js 20.9 or later (22 LTS recommended).

```bash
npm install
cp .env.example .env
```

On Windows PowerShell: `Copy-Item .env.example .env`

Get `DATABASE_URL_POOLED` (pooled) and `DATABASE_URL` (direct/unpooled) from your **Neon project dashboard**. Use SSL-enabled URLs. Set `RATE_LIMIT_SECRET` to 64 or more random hexadecimal characters generated by `openssl rand -hex 32` or a password manager. Change `NEXT_PUBLIC_SITE_URL` in production.

```bash
npx prisma generate
npx prisma migrate deploy
npm run db:seed
npm run admin:create
npm run dev
```

Visit `http://localhost:3000` for the website and `http://localhost:3000/admin/login` for staff login. The admin creation command prompts for email, name and a password (12+ characters, at most 72 UTF-8 bytes; **hidden while typed** — run it privately). Do not run admin creation on a public/shared terminal.

The ZIP includes an initial SQL migration under `prisma/migrations/`. Production setup uses `npx prisma migrate deploy`, then `npm run db:seed` and (once) `npm run admin:create` in a secure environment. For future schema changes, run `npx prisma migrate dev --name your_change` in development and commit the new migration. Run the admin create command once only; thereafter use **Staff Users** as an admin.

## Admin authentication

See [the implementation and setup walkthrough](docs/authentication.md) for the login flow, JWT/cookie security, RBAC and changed files. Customer login and customer rating submission have been removed. Staff sign in at `/admin/login` using credentials assigned by the business. `ADMIN` is the only staff role. Configure `ADMIN_JWT_SECRET` as 64 random hexadecimal characters, independently of `RATE_LIMIT_SECRET`.

## 2. Booking flow

1. Customer picks a car from `/cars` or its detail page.
2. **Quick WhatsApp** button navigates to `GET /api/whatsapp/[slug]`, which looks up the _current_ published/available car, current admin-configured WhatsApp number, and redirects to `https://wa.me/<number>?text=<encoded message>`.
3. On detail pages, customers enter name, phone, pickup location, dates, notes. `POST /api/booking-intents` validates/rate-limits the request, writes an **enquiry record** to Neon and returns the same WhatsApp deep link with all details. Browser opens WhatsApp after saving.
4. Admin follows up manually, changes booking status from NEW to CONTACTED, CONFIRMED, COMPLETED, CLOSED or CANCELLED. Only confirmed rentals returned to staff should be marked COMPLETED. Admins can also export a CSV of form enquiries.

**Important:** The WhatsApp API link does **not** prove the customer sent the message, and direct one-click WhatsApp links are **not** logged as booking enquiries. Neither action confirms availability, reserves inventory, processes payment, or creates a confirmed booking. Admin statuses are manual. To automate delivery/read receipts, integrate an approved WhatsApp Business Platform provider + webhooks separately (not included).

## 3. Admin functions

At `/admin` dashboard: fleet/area/lead/review counters, recent enquiries.

- **Cars:** add/edit/delete cars, publish/unpublish, mark unavailable, price tiers, km/hour charges, photos (HTTPS URL or optional authenticated Cloudinary upload), gallery (URL list), specifications, order and featured label. Delete is blocked for cars with enquiries; unpublish instead.
- **Locations:** create/edit/delete delivery areas, toggle active.
- **FAQs:** manage and publish question/answer sections.
- **Testimonials:** draft/edit and publish only genuine reviews with customer permission; optional verification flag. Sample testimonials are _not_ seeded.
- **Bookings:** inspect saved enquiries, update statuses, export most recent 10,000 to CSV.
- **Settings:** manage live contact/WhatsApp number, email, address, website headings and Google Maps URL.
- **Staff Users (admin):** create/edit/delete administrator accounts, deactivate, reset password. There is one staff role: ADMIN. Cannot delete own account. Sign-ins are invalidated when password is changed or account disabled.
- **Audit Trail (admin):** write actions for the main admin resources.

**Media handling:** Admin image fields accept pre-hosted HTTPS URLs or files placed in `public/cars`. Optional Cloudinary signed uploads are supported by setting `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY` and `CLOUDINARY_API_SECRET` in `.env`. The secret stays server-side; the uploader validates image MIME/signature, enforces a 3MB per-file limit and rate-limits uploads. Add malware scanning, image moderation, deletion/garbage collection policies and hardened request-body streaming limits for high-volume production. Without Cloudinary credentials, enter HTTPS URLs instead. Do not use the screenshots' sample extracted images without the image owner's permission; they are demo/reference assets and should be replaced with licensed, real fleet photos.

## 4. Security checklist

Implemented:

- Zod server-side validation and allowlisted resource endpoints; no generic Prisma queries from client input
- Server-side ADMIN authorization, signed one-hour JWTs, token hash and expiry stored in DB for immediate revocation
- HttpOnly, SameSite=Strict cookie with a production Secure/__Host- prefix; session revoked on logout and credential changes
- bcrypt password hashes (12 rounds), 12-character minimum; admin-only staff management
- Database-atomic login/enquiry rate limits across server instances; salted/HMAC-derived IP fingerprints
- Same-origin validation for POST/PATCH/DELETE requests; JSON content-type and size checks
- Role checks enforced inside API handlers; protected admin pages and private audit data
- Restricted image URL protocol; React's escaped render; server-side WhatsApp number selection
- No credentials in source, security response headers, anti-clickjacking settings, no-store for sensitive responses

Before real deployment:

1. Enable SSL/HTTPS, Neon backups, operational monitoring, and a secure secret-management service.
2. Configure hosting proxy to **overwrite** `x-forwarded-for` / `x-real-ip`, not trust a client-supplied IP, or adapt `clientFingerprint` to the platform's verified client-IP facility.
3. Add MFA / passkeys for administrators if deploying publicly. This example includes password-only admin login and is not a security-audited production system.
4. Introduce a privacy notice, retention/deletion workflow for booking customer names and phone numbers, and applicable consent for contact.
5. Confirm car prices, insurance, permit, maintenance, ownership, and zero-deposit policies with the business before publishing.
6. If strict CSP is required, deploy a nonce-based CSP integrated with Next.js, accounting for HeroUI styles. The bundled minimal CSP avoids breaking hydration.
7. Add integration/e2e tests, observability and a staging environment before accepting customer traffic.
8. Set `NEXT_PUBLIC_SITE_URL` to the final `https://...` domain, and use a host with stable environment configuration.

## 5. Notes and limitations

- Automated tests cover JWT signatures and expiry, admin-only RBAC, bcrypt hashing, session revocation, CSRF, login throttling, secure cookies, guest enquiries and PostgreSQL constraints.
- Seed car prices/specifications and fallback assets are **illustrative**. Business should verify them.
- The starter does not implement realtime inventory locking, calendar overlap prevention, deposits, refunds, live WhatsApp chat inbox, or payment processing.
- HeroUI v3 is used for accessible form action buttons; layout/cards use custom responsive CSS for closer visual matching to the screenshots.
- All public pages read published data from Neon and work when seeded. The `/sitemap.xml` dynamically lists published cars.
- Email, passwords and real Neon connection details must **never** be committed to git.
